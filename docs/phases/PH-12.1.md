## Affected boundaries and implementation approach
- BL-027 — `maskLikelySecrets(text)` in `packages/shared/src/access.ts`: a token after a keyword that announces a secret (senha, password, código, code, pin, token, otp, 2fa, frase de recuperação, seed) is masked when it looks like one (digits, or a long mixed-case word); a bare 6–8 digit number is masked as a one-time code; words about secrets ("a senha nunca chega") stay. The API applies it in the staff projection (`descriptionMasked` on the request); the row keeps the original for the verification process; the staff page shows a note under a masked description.
- BL-028 — `case_notifications.email_attempts` and `email_failed_at` (migration `0023`); a failed send counts an attempt and, at `SUPPORT_EMAIL_MAX_ATTEMPTS` (5), parks the row as a dead letter with an error in the log; dead letters are not selected again; the in-product notification is untouched.
- BL-030 — `check-context` also reads repository paths (`apps/…`, `packages/…`, `scripts/…`, `docs/…`, `docker/…`) in `scripts/*.sh`, `docker/*`, `.github/workflows/*.yml` and `.env.example` (container paths with a leading `/` or `./` are not repository paths; git-ignored build outputs are skipped).
- BL-017 — `@nestjs/mau` (the Nest deploy CLI, never used) and its `deploy` script removed from `apps/api`; the undici advisories came through it. What remains is dev-only: drizzle-kit's loader depends on an old esbuild (a dev-server advisory), and every drizzle-kit version depends on it — accepted until its next major.
